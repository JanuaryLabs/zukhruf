# A job is the typed launchd.plist(5), with Apple's key names

The maintainer said: "no untyped stuff." (DeepSeek session a5d700c2, 2026-11-15). A job may not pass an untyped dictionary through to the job file.

launchd.plist(5) on macOS 27.2 documents 55 keys at the top level and 36 nested keys: `Wait` of `inetdCompatibility`, 6 conditions of `KeepAlive`, 5 fields of a calendar interval, 9 resource limits, 2 keys of a Mach service and 13 keys of a socket (research record, 2026-11-15). The leading tools model them in three ways:

- **Apple's names, with types.** nix-darwin types 46 of the 55 keys in `serviceConfig` and leaves `LaunchEvents` untyped (`types.attrs`). The Rust crate koenichiwa/launchd types 54 of the 55 and leaves `LaunchEvents` a `plist::Value`.
- **A model of its own, mapped to the keys.** The service DSL of Homebrew has its own names, and its map gets three keys wrong. It writes only one `KeepAlive` condition (`service.rb:634-644`), although launchd "ORs them" when there are more (launchd.plist(5), lines 191-193). It writes `PathState` as a string (`service.rb:642`), although the page gives a "dictionary of booleans" (lines 219-222). Its `restart_delay` writes `TimeOut` (`service.rb:620`), which "never did anything interesting and is no longer implemented" (lines 313-315).
- **No types.** No npm package types all the keys. The package `launchd.plist` names 40 of the 55, and the others name 10 or fewer.

A model of its own needs a map, and each map is a place for such a bug. Apple's names need no map, and the man page is their documentation.

## Considered Options

- **A model of its own, as Homebrew.** It needs a map from its names to Apple's keys, and Homebrew's map shows three bugs of that kind.
- **Apple's names, with an untyped dictionary for the rest, as nix-darwin and the Rust crate.** `LaunchEvents` is then untyped. The maintainer refused untyped values.
- **Each live key of launchd.plist(5), with Apple's name and a type from the page, and `LaunchEvents` typed by xpc_events(3).** This option was selected.

## Consequences

- `Job` has Apple's key names and value types. A wrong name or a wrong type fails the type check. A key comes into the type when launchd.plist(5) documents it.
- Where the page lists the values, the type is a union of them: `ProcessType` (lines 483-510), `SockType` (lines 588-591), `SockFamily` (lines 606-610) and `SockProtocol` (lines 612-615). `LimitLoadToSessionType` takes `Aqua`, `Background` or `LoginWindow`, the session types of launchctl(1) (lines 395-401). The fields of a calendar interval are unions of their ranges: `Minute` 0-59, `Hour` 0-23, `Day` 1-31, `Weekday` 0-7 and `Month` 1-12 (launchd.plist(5), lines 380-395). The page gives no type for `MaterializeDatalessFiles` (line 526), and its text sets it to true or false, so it is a boolean.
- A key whose value is a path takes an absolute path, `` `/${string}` ``. launchd runs the program with execvp(3) and no shell (lines 136-140), so it expands no `~` and no `$HOME`. The page says that "The Program key must be an absolute path" (lines 142-143). The first item of `ProgramArguments`, when there is no `Program`, "may be either an absolute path, or a relative path which is resolved using \_PATH_STDPATH" (lines 144-146), so it stays a `string`. `_PATH_STDPATH` is `/usr/bin:/bin:/usr/sbin:/sbin` (`paths.h:67` of the macOS SDK), not the `PATH` of the caller.
- `Program` or a non-empty `ProgramArguments` is required. A union holds this rule. A job can have both: then `ProgramArguments` is the whole argument vector with its item 0, as in the example of the page (lines 719-726).
- Agents and daemons have different keys. `UserName` and `GroupName` are "only applicable for services that are loaded into the privileged system domain" (lines 74-83), and `InitGroups` is ignored when `UserName` is not set (lines 333-337). `LimitLoadToSessionType` "only applies to jobs which are agents" (lines 104-107). Thus `AgentJob` adds `LimitLoadToSessionType` to `Job`, and `DaemonJob` adds the three keys of the user. `install()` of agents takes an `AgentJob`, and `install()` of daemons takes a `DaemonJob`.
- `LaunchEvents` is typed by xpc_events(3). "These are currently the only two supported event streams": `com.apple.iokit.matching` and `com.apple.notifyd.matching` (xpc_events(3), lines 29-34). An event of the notifyd stream is `{ Notification: string }` (lines 68-79). An event of the IOKit stream is a matching dictionary, in which "The IOMatchLaunchStream key is required to be present and be a Boolean set to true" (lines 89-92), so the type requires `IOMatchLaunchStream: true`. Typed launch events go beyond each surveyed tool.
- A matching dictionary is open by the design of IOKit: a key that is not a matching key names a property that the device must have, such as `idVendor` and `idProduct` in the example of xpc_events(3) (lines 58-63). A probe of the job files of macOS 27.2 in `/System/Library/LaunchAgents` and `/System/Library/LaunchDaemons` found such properties beside the matching keys (`VendorID`, `ProductID`, `DeviceUsagePage`), with string, integer, boolean, array and dictionary values. Thus `MatchingDictionary` types `IOMatchLaunchStream` and `IOProviderClass`, and each other key takes a `PropertyListValue`: a string, a number, a boolean, an array or a dictionary of these. The matching keys are in `IOKitKeys.h` of the macOS SDK (lines 88-102). No value is `unknown`.
- Other dictionaries have keys that the caller names, and typed values: `EnvironmentVariables` (strings, lines 295-300), `MachServices`, `Sockets`, `LimitLoadToHardware`, `LimitLoadFromHardware`, and `PathState` and `OtherJobEnabled` of `KeepAlive`.
- A socket is one of three forms, because the page ties some keys together. "This optional key implies SockFamily is set to "Unix"" (`SockPathName`, lines 617-619), and `SecureSocketWithKey` "is a variant of SockPathName" (lines 621-625). Thus a socket has `SockPathName`, or `SecureSocketWithKey`, or the keys of a network socket (`SockNodeName`, `SockServiceName`, `SockFamily`, `SockProtocol`, `Bonjour`, `MulticastGroup`), and never keys of two forms. `SockType` and `SockPassive` go with each form.
- The same probe found more than 20 other stream names in Apple's own job files, such as `com.apple.xpc.activity`. The page does not support them, so a job cannot have them.
- The keys that the page calls discouraged stay in the type, because they still work: `inetdCompatibility` (lines 86-88), `RunAtLoad` (lines 259-261), `RootDirectory` (lines 280-289), `WatchPaths` (lines 343-347), and `PathState` (lines 237-239), `OtherJobEnabled` (lines 246-249) and `HideUntilCheckIn` (lines 565-569).
- The type has 46 of the 55 top-level keys, and 35 of the 36 nested keys. It leaves out these keys:
