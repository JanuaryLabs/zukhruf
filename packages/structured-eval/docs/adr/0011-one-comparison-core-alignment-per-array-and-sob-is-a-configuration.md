# One comparison core: the alignment of each array is a Strategy, and SOB is a configuration in its caller

Status: Accepted 2026-11-06 by Ezz (backlog #3884), as a whole and with three fixes: the type walk reads the schema with the draft of the validator, the draft is a setting of `JsonSchema`, and ADRs 0006 and 0007 get a status line. The decisions below come from standards and precedents, and Ezz approved them as a whole. This ADR replaces [ADR 0003](0003-sob-parity-is-a-separate-lossless-port-of-evaluate-py.md) and amends ADRs 0002, 0004, 0005, 0006, 0007, 0008 and 0009.

Amended by [ADR 0012](0012-a-penalty-multiplies-the-part-of-a-ratio-and-the-caller-scores-each-subset-with-its-own-scorers.md) (accepted 2026-11-06): `Penalized` replaces `Gated`, and a gate is a penalty with the factor 1 or 0.

## Context

The package has two engines. `src/paths` scores a stated value leaf by leaf, as SOB's evaluate.py does. `src/records` compares a stated record with an expected record field by field. Each engine has its own copy of the same knowledge:

| Knowledge                    | `src/paths`                        | `src/records`                 |
| ---------------------------- | ---------------------------------- | ----------------------------- |
| The walk of the leaves       | `JsonPair` (a path is a string)    | `RecordLeaves`, `RecordWalk`  |
| The alignment of array items | by position, with no class         | `ByPosition`, `ByBestMatch`   |
| The agreement of two values  | `LeafExactMatch` (Python `==`)     | `Exact` (`isDeepStrictEqual`) |
| Token F1                     | `LeafTokenF1`                      | `Words` and `TokenCredit`     |
| The JSON Schema validator    | `Draft7Schema`                     | `RecordSchema`                |
| The types that a path allows | `SchemaTypeWalk`                   | `SchemaTypes` (backlog #3859) |
| The F1 arithmetic            | `PathF1`, `LeafTokenF1`: 2pr/(p+r) | `Words.f1`: 2s/(a+b) (#3852)  |

Ezz read the two engines and said: "I cannot make sense of paths and records", and "should we have both? why sop have one?".

SOB has one rule for arrays. evaluate.py writes the address of a list item with its index (`flatten_leaf_paths`, `f"{prefix}[{idx}]"`, evaluate.py:389-420). So SOB always pairs the items of an array by position. CONTEXT.md already names that rule: an alignment by position. `src/records` already has that alignment as `ByPosition`. So SOB's rule is one setting of a concept that the package already has.

ADR 0003 kept SOB parity separate: "one flag on the spec would mix the two methods in one scorer". The two methods were the pairing of items and the average. Since then, ADR 0005 and ADR 0009 made each SOB number a composition of scorers, and SOB's caller keeps that composition. So a setting of the pairing and a choice of the average are now the caller's work. They are not a flag on one scorer.

Ezz also gave the rule for the consumers: "we are to force consumers to follow us, not the other way around". The package is the standard. offers-evals and startup-credits change to follow it.

## Decision

The package has one comparison core:

1. One value model: `JsonData` of @zukhruf/python. A plain JavaScript value enters only at the boundary, through `JsonValue.from`. Python's `True == 1` is a comparator, not a value model.
2. One walk, `TreeWalk`. It compares a stated value with the expected value of its case and gives a `Comparison`. A `Path` is a list of steps (keys and indexes), not a string.
3. The alignment of each array is a Strategy (`Alignment`): `ByPosition` (the default) or `ByBestMatch(match)`, the Hungarian algorithm. `ComparisonSpec.arrays` sets the alignment of each array.
4. The agreement of two values is a Strategy (`Comparator`). The default of the spec is `JsonEquality`. `ComparisonSpec.fields` sets the comparator of one field, such as `NumberWithin`.
5. One schema, `JsonSchema`: a Facade over the cfworker validator, with the one lookup of backlog #3806 and the one `SchemaTypeWalk`. `SchemaTypes` is deleted. The draft is a setting of `JsonSchema`: `new JsonSchema(value, { draft })`. The validator and the walk read the schema with that one draft, so one schema has one meaning. A case reader builds the `JsonSchema` of each case, and it takes the function that builds it.
6. A scorer gives a `Ratio` for one comparison. `Precision`, `Recall` and `F1` read the counts of a `Matches`: `PathMatches`, `ValueMatches` or `ItemMatches`.
7. The average is the caller's choice. A plain scorer gives a ratio with its counts, so `Totals` gives the micro average. `SampleAveraged` gives a ratio over 1, so `Totals` gives the samples average (the mean of the values of the records).
8. SOB is a configuration in its caller: `ByPosition`, `PythonEquality`, a `JsonSchema` read as draft 7 (for the validation and the walk), and `SampleAveraged` on each scorer. The golden test and offers-evals compose it.

### The exception of `F1Ratio`

A `Ratio` gives the part divided by the whole. `F1Ratio` is a named exception to that rule. Its part is 2·hits and its whole is stated + expected, so many F1 ratios add up as a micro F1. Its value is 0 when there are no hits, else 2·p·r/(p + r), the arithmetic of evaluate.py. That value can differ from part/whole in the last bit, such as for 1 hit of 1 expected and 5 stated. So one record gives evaluate.py's bits, and many records give the micro F1. `F1Ratio` is the one home of the F1 arithmetic (backlog #3852). A test proves both faces.

## Considered Options

- (a) Keep two engines. Each fix goes into two copies, and the two copies already differ: `SchemaTypes` disagrees with `SchemaTypeWalk` (#3859), and the two token F1s give different bits. A reader cannot tell which engine to use.
- (b) One core for records, and an exact SOB port behind a hook. lm-evaluation-harness does this for DROP: its task keeps the official metric in a `process_results` function, because the official metric has quirks. Here, ADR 0005 and ADR 0009 already made SOB a composition of scorers in its caller. Each SOB quirk has a home in the core: a Strategy (`ByPosition`, `PythonEquality`), a parameter (`whenEmpty`, `absentAs`, `nullIsMissing`, the draft of the schema), or a scorer named by what it measures (`RequiredKeyRecall`). A hook would bring back the second engine.
- (c) One core, with the alignment of each array as a Strategy and SOB as a configuration in its caller. This option was selected.

## Consequences

- ADR 0003 is replaced. Its rules about Python's results stay true, with new homes: the value model is `JsonData`, Python's `==` is `PythonEquality`, and the bootstrap draws with `python-random` in the golden test.
- ADR 0002: maximum matching is `ByBestMatch`. The micro average is what a plain scorer gives. SOB numbers come from `ByPosition` and `SampleAveraged` in SOB's caller, not from a separate port.
- ADR 0004: a scorer gives a `Ratio`, not a scorecard of measures. `Gated` multiplies the part of a ratio. The rule "`scoring/` and `aggregation/` import nothing from `records/` or `paths/`" goes, because those folders go.
- ADR 0005: the scorers have new names. `LeafExactMatch` is `Recall(ValueMatches)`, `PathRecall` is `Recall(PathMatches)`, `PathF1` is `F1(PathMatches)`, `LeafTokenF1` is `TokenF1`, and `LeafTypePrecision` is `TypePrecision`. A benchmark stays a composition in its caller.
- ADR 0008: type precision follows the draft of the schema, the same draft as the validator. SOB's caller sets draft 7, so ADR 0008's draft 7 walk stays for SOB. Under 2020-12, the walk also reads `prefixItems`, and `items` is the schema of the items after them. `SchemaTypeWalk` reads the steps of a `Path`, so it no longer parses a string. It is the one walk of the types: `SchemaTypes` is deleted, and that closes #3859. `whenNoneStated` becomes the `whenEmpty` of `SampleAveraged`.
- Decision 3: a key that holds `.`, `[` or `]`, and an empty key, now get scores that are different from the scores of evaluate.py, but on 2026-11-06 the offers-evals kit and the SOB golden fixture (10,457 records together) had 0 of these keys.
- Decision 3: the dotted form of a key, such as `offers[].value.amount`, throws. It has no alias. Each consumer writes JSONPath, such as `$.offers[*].value.amount`. A label of `PerField` and an explanation of a gate write fields and paths as JSONPath too, such as `$.offers[*].kind recall` and `$.offers[2].kind`.
- ADR 0006 and ADR 0007: `JsonPair` is replaced by `Comparison`, and `JsonTextCase` is replaced by `TextVarsCase`. One assertion for each scorer, with the case from the vars of the test, stays.
- ADR 0009: `Scorer.score` reads a `Comparison` and gives a `Ratio`. The scorers are in `src/scorers/`. A `ScorerSet` passes when each of its gates holds.
- ADR 0010 does not change: `Bootstrap` still adds the ratios of one name.
- The folders `src/paths` and `src/records` go away. The new folders are `comparison/`, `schema/`, `scorers/`, `scoring/`, `aggregation/`, `cpython/` and `promptfoo/`. That closes #3883.
- These classes are deleted: `JsonPair`, `RecordWalk`, `RecordLeaves`, `RecordVisitor`, `LeafMean`, `Words`, `TokenCredit`, `Draft7Schema`, `RecordSchema`, `NoSchema`, `SchemaRule`, `Validity`, `SchemaTypes`, `ItemPairing`, `Differences`, `Exact`, `RecordSpec`, `RecordCase`, `RecordScorer`, `JsonCase`, `JsonTextCase` and `JsonTextScorer`.
- The F1 arithmetic is in one place, `F1Ratio` (#3852). docs/copied-code.md loses the `PathF1` → `LeafTokenF1` copy.
- A `Match` reads `JsonData`. A match that reads plain JavaScript, such as startup-credits' `SameSentence` with zod, converts the value with `toJsonParseValue` of @zukhruf/python first.
- Records change on purpose. An invalid record gives precision Ratio(0, stated), not Ratio(0, 0). A text answer gives type precision Ratio(0, 0). Token F1 of records loses NFKC, removes the articles, and takes evaluate.py's bits. The reason of a scorecard comes from the explanations of the gates that fail. A `format` no longer fails a record.
- The code is in the package. The six slices of #3884 built it, and each slice kept every oracle green: the SOB golden test, the offers-evals kit, and the promptfoo test of startup-credits.

## Precedents

Sources fetched on 2026-11-06.

- SOB, evaluate.py at da785a8, `flatten_leaf_paths` (evaluate.py:389-420): the address of a list item is its index, so every array pairs by position.
- DocILE, `line_item_matching.py:11-62`: line items pair by a maximum-weight bipartite matching (networkx `minimum_weight_full_matching`), and the metric is a micro F1 over TP, FP and FN.
- DROP F1 in lm-evaluation-harness: the bags of an answer pair by the Hungarian algorithm (`scipy.optimize.linear_sum_assignment`). The task keeps the official metric behind `process_results`.
- ExtractBench (`array_metrics.py`, `metric_registry.py`): each node of the schema has its own `evaluation_config`, from a registry of metrics. Its paper says that a pairing by position fails when the items change order.
- DeepDiff: ordered by default; `ignore_order_func(level)` sets the order rule for each path, `iterable_compare_func` says when two items are the same item, and `exclude_paths` leaves paths out.
- scikit-learn, `precision_recall_fscore_support`: `average='micro'` adds the counts first; `average='samples'` takes the mean of the value of each sample.
- Benchmark as a configuration: lm-evaluation-harness task YAML (`metric_list` with parameters, versioned), inspect_evals (a general scorer with arguments, such as `f1(extract_answer)`), and HELM (`MetricSpec` factories).
- Value model: the TC39 proposal "JSON.parse source text access" is finished, and Node 26 gives the reviver `context.source`, so `'1.0'` and `'1'` stay apart. The reviver sees objects that `JSON.parse` already built, so it does not keep the order of the keys. `JsonData` stays the value model.
