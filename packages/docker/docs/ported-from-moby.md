# Ported from Moby and the Docker CLI

`src/dockerignore.ts` is a port of the `.dockerignore` rules of the Docker CLI (Apache-2.0 and BSD-3-Clause, see `NOTICE`). [ADR 0016](./adr/0016-an-image-build-sends-a-tar-context-to-buildkit-through-the-engine-api-and-the-caller-pulls-each-base-image-first.md) gives the reason: no npm package sends the files that the CLI sends. When a source changes, compare the source at the new commit with the commit on the left, and make the same change here.

## Differences

- **Part of the rules of Windows waits for a run on Windows.** As Go keys them on `os.PathSeparator`, the port keys them on `process.platform`. As in Go, `compile` takes the separator as its argument, so its regexp for `\` (a separator that escapes nothing) is proved on each platform by the cases of `TestCompile`. The rest runs only on Windows: `filepath.Match` with no escape, `filepath.Clean` through `path.win32` (in `readDockerignore` and the matching), `FromSlash` and `ToSlash`, and the walk with `\`. Go has no test of them that runs on each platform. They wait on the Windows job of backlog #2753 (a Windows host, or a `workflow_dispatch` job on `windows-latest`), where `src/dockerignore.test.ts` runs as it is. Its table leaves out the cases that `patternmatcher_test.go` leaves out on Windows (lines 195-199 and 459-463).
- **Escapes that Go's regexp reads and `filepath.Match` does not.** A pattern compiles to a Go regexp, and Go reads an escaped letter or digit (`\d`, `\w`, `\pL`, `\x41`, `\Q`) and a POSIX class (`[[:alpha:]]`) as regexp syntax. The port refuses such a pattern with the `SyntaxError` of a malformed pattern, so that a folder never sends other files than the CLI sends. Go refuses the other escaped letters too.
- **An error stops the walk.** `Tarballer.Do` logs an error of the walk, and of a pattern that fails to compile at its first match, and sends the tar that it has. `contextPaths` throws it, so that a build never sends part of a context.
- **No Dockerfile from standard input.** `TrimBuildFilesFromExcludes` has a `dockerfileFromStdin` flag; the package has no standard input, so the Dockerfile is a path in the context.
- **Text, not bytes.** The port reads the `.dockerignore` as UTF-8 text and compares code points, where Go compares bytes. The two differ only on bytes that are not UTF-8. A line longer than the 64 KiB of `bufio.Scanner` is a pattern here and an error in Go.
- **Two steps of Go that a later step of the port already does.** `bufio.ScanLines` drops the `\r` before each `\n`; `readDockerignore` leaves it to `trimSpace`, which drops it from each pattern, and a comment is still a line that starts with `#`. `parseClass` refuses a range out of order (`[z-a]`); `goRegExp` leaves it to the `RegExp` that it builds, which refuses the same range. A mutation that drops either step changes no result, so the port has neither step.
