# Ported from MTEB

This package is a port of the evaluation engine of [MTEB](https://github.com/embeddings-benchmark/mteb) 2.26.28 (Apache-2.0, see `NOTICE`). Each TypeScript module has one Python source module. When MTEB changes, compare the source module at the new tag with the tag on the left, and make the same change here.

The first step ports the core and the retrieval and reranking tasks, for text. The second step ports the pair classification tasks, for text. The third step ports the STS tasks, for text. The fourth step ports the clustering tasks, for text. The fifth step ports the classification tasks, for text. The sixth step ports the multilabel classification tasks, for text. The other task types (regression, zero-shot) and the other modalities (image, audio, video) come later. The types keep the modality fields of MTEB, so that a later step adds a modality without a change of design.

## Conventions

- The public API of a ported class is the public API of its MTEB class, also where this package does not call a method yet (`TaskResult.merge`, `ResultCache.getModels`, `ModelMeta.openness`, the `remote/` folder of a cache that MTEB filled). A Python method that starts with `_` and has no caller here is not ported.
- Classes keep their Python names (`AbsTaskRetrieval`, `TaskMetadata`). Functions, methods and fields take the camelCase form of the Python name: `calculate_retrieval_scores` is `calculateRetrievalScores`, `hf_split` is `hfSplit`. A Python method that starts with `_` is a `#` member, or a function that the module does not export.
- Keyword-only parameters become one options object. Positional parameters stay positional.
- Encoding, search, loading and `evaluate` are async, because an encoder calls a model over the network. MTEB's are synchronous.
- A HuggingFace `Dataset` is an array of rows. A Python `dict` that maps ids is a `Map`: a `Map` keeps insertion order for every key, and an object moves integer-like keys such as `"0"` to the front.
- An MTEB `Array` (a numpy array or a torch tensor) is `Embeddings`, one `Float32Array` for each row. Embeddings and similarity scores are float32, as in MTEB; the other numbers are float64, as in Python.
- A pydantic model is a zod schema and a class. Files on disk keep the keys, the structure and the `NaN` values of MTEB, so MTEB and this package read the files of each other.
- Numbers follow the Python algorithms where the result can differ: `sum` of floats is Neumaier summation (CPython 3.12), `round` rounds half to even, a numpy sum is a pairwise sum (`@stdlib/blas-ext-base-gsumpw` 0.3.1, which adds in the order of numpy's add loop), and ties sort as Python tuples sort.

## Differences

- Not ported: logging, tqdm progress bars, the CO₂ tracker (codecarbon), device selection and `torch.compile`, `num_proc`, the remote result repository of the HuggingFace Hub and `submit_results`, the leaderboard, the lookup of tasks and models by name (`get_task`, `get_model`; the ported tasks are classes and the ported models are `ModelMeta` values), descriptive statistics, search index backends (`index_backend`), and the `encode` and `similarity` methods of `SearchEncoderWrapper`, which only pass the call to the wrapped model and have no caller here. A retrieval task loads its dataset from the HuggingFace Hub or from a folder on disk (see Datasets below); any task can override `loadData`.
- The similarity scores are float32, but the summation order of a BLAS matrix product depends on the library and the processor. Thus a score can differ from MTEB in its last float32 bit, and so can the nAUC values that use the scores. The trec_eval measures, the MRR and the rounded scores are the same when the scores are the same.
- MTEB's encoders over text models share `AiSdkTextEncoder` (`models/ai-sdk-text-encoder.ts`), which has no Python module of its own: it sends the texts to an AI SDK embedding model in batches, gives float32 embeddings and adds up the tokens. `AiSdkEncoder`, `InstructAiSdkEncoder` and `EmbeddingGemma2Encoder` give the text of each input, as `OpenAIAPIEncodeWrapper`, `InstructSentenceTransformerModel` and `EmbeddingGemma2Wrapper` do.
- Datasets: `AbsTask.loadData` loads the dataset of the metadata as MTEB's `load_data` does, with `loadDataset` of `dependencies/datasets.ts`. It loads all splits of the config of each subset of a multilingual task, or of the config that `dataset.name` names. Then it runs `datasetTransform`. A task whose split data is not a `Dataset` gives its data in `loadSplits`, as `AbsTaskRetrieval` does. `loadDataset` reads JSON, JSON Lines and parquet files, and gzip files of JSON. It finds the data files of each split from the configs of the dataset card. When the card has no configs, it finds them from the names of the files and folders, as datasets 5.1.0 does. It casts to the features of the card for numbers, strings, booleans, class labels and lists of these. It throws for other file formats, other archives, `dataset.split`, a `.huggingface.yaml` file and other casts. The first file of the first split sets the columns of all splits, but the port does not compare the types of the other files. A JSON integer above 2^53 is not exact, as in JavaScript, and a struct keeps the key order of its row. A row is an object with the column names in order; Python's `Dataset` is a table of columns. The port keeps the downloaded files of a Hub repository in `~/.cache/mteb/datasets/<repository>/<revision>/`, and the file list of the revision in `~/.cache/mteb/datasets/<repository>/<revision>.files.json`.
- Datasets: `RetrievalDatasetLoader` reads the configs of the dataset card (`README.md`) of the repository at its revision, and downloads the data files of a split from `<endpoint>/datasets/<repository>/resolve/<revision>/<path>`. It reads JSON Lines files only, and does not infer data files for a card without configs. It keeps the files in `~/.cache/mteb/datasets/<repository>/<revision>/`, not in the cache of the datasets library. The qrels of a query keep the order of the file; MTEB's `group_by(maintain_order=False)` has no fixed order. When the repository is a folder on disk, the loader reads the files of that folder, as `load_dataset` reads a local path (`datasets/load.py`: `os.path.isdir(path)`). It does not use the revision or the cache for a folder.
- Pair classification: `AbsTaskPairClassification` gives each pair five scores: the cosine similarity, the Euclidean distance, the Manhattan distance, the similarity of the model and the dot product. The metrics of each score are the accuracy, F1, precision, recall and average precision. These metrics use only the order of the scores and the labels. Thus they are equal to the metrics of MTEB when the scores have the same order. The Manhattan distance adds float32 values in the pairwise order of numpy, so it is equal to MTEB to the last bit. MTEB calculates the other four scores in float32 with `np.einsum`, BLAS `sdot` or torch, and the order of addition depends on the library and the processor. This package adds those sums in float64 and rounds each sum to float32 once. Thus such a score can differ from MTEB in its last float32 bits.
- Pair classification: text only. A task with another modality, or with a map of columns in place of a column name, throws. The descriptive statistics, the push to the Hub and `_encode_unique_texts` (MTEB has no caller) are not ported. `computeMetrics`, `computeMetricsValues`, `findBestAccAndThreshold` and `findBestF1AndThreshold` are protected methods, not `#` members, so that a task can override them, as a Python subclass can. The `__call__` of `PairClassificationEvaluator` is `call`. `compute_pairwise_similarity` falls back to the cosine when a model has no `similarity_pairwise`; each encoder here has `similarityPairwise`, so the evaluator calls it.
- STS: `AbsTaskSTS` gives each pair four scores: the cosine similarity, the negative Manhattan distance, the negative Euclidean distance and the similarity of the model. For each score, it calculates `pearsonr` and `spearmanr` of SciPy with the gold scores, which `normalize` scales to 0 to 1. `spearmanr` is `np.corrcoef` of the average ranks of `rankdata`. A centred rank is a multiple of 0.5, so each sum of products in `np.corrcoef` is exact in any order, for fewer than 2 ** 18 pairs. Thus the Spearman correlation of the same scores is equal to MTEB to the last bit. `pearsonr` adds the products of the centred and scaled scores with `np.vecdot`, which calls BLAS `ddot` (Accelerate on macOS). The order of addition of `ddot` depends on the library, the processor and the number of values. The port adds in order, as `ddot` of Accelerate does for fewer than 4 values. Thus a Pearson correlation of the same scores can differ from MTEB in its last bits. The scores themselves are those of pair classification: the negative Manhattan distance is equal to MTEB to the last bit, and the other three can differ in their last float32 bits. Thus a Pearson correlation of those three can differ from MTEB by about 1e-7, and so can a Spearman correlation when such a difference changes the order of two scores.
- STS: text only. A task with another modality, or with a map of columns in place of a column name, throws. The descriptive statistics and the push to the Hub are not ported. `calculateScores` and `normalize` are protected methods, not `#` members, so that a task can override them, as a Python subclass can. The `__call__` of `AnySTSEvaluator` is `call`. `similarity_scores` is never `None`: each encoder here has `similarityPairwise`. A gold score that is not a number or a bool throws a `TypeError` with the message of this package. `STSBenchmarkSTS.v2` is not ported.
- Clustering: `AbsTaskClustering` embeds a sample of the inputs of a split: by default 4%, which `rngState.sample` selects. `rngState` is CPython's `random.Random` with the seed of the task (`dependencies/python-random.ts`), so the port selects the inputs of MTEB. For each level of the labels, the task draws 10 sets of 16384 embeddings with `rngState.choices`. It clusters each set with `MiniBatchKMeans` and calculates the V-measure and the adjusted mutual information (AMI). The main score is `v_measure`, the mean of the V-measures. For an input without a label at a level, MTEB gives the label -1, and numpy makes it the string `"-1"` when the other labels are strings. Thus with string labels, the input stays in that level with the label `"-1"`, as in MTEB. With int labels, the input leaves the level.
- Clustering: `MiniBatchKMeans` (`dependencies/sklearn-kmeans.ts`) draws from numpy's legacy `RandomState` (MT19937) as scikit-learn does: the validation and init indices, k-means++, the minibatches and the reassignments. It updates the centers with float32 operations in the order of scikit-learn. scikit-learn calculates the distances to the centers with BLAS. The port adds each dot product in float64 and rounds once. Thus a distance can differ in its last float32 bit, and a sample at almost the same distance from two centers can get another label. When the labels are the same at each step, the centers are equal to the last bit. The early stop compares a float32 average of the inertia of the batches. The port adds the inertia in order; scikit-learn adds it in OpenMP threads.
- Clustering: the V-measure calls the correctly rounded `log` of `dependencies/libm.ts`, not `Math.log`. `Math.log` and the `log` of macOS give different floats for about 1% of the integers. The `log` of macOS is not correctly rounded for 1 integer from 1 to 16384 (9170), and for about 60 in a million integers above. When the V-measure takes the log of such an integer, it can differ from MTEB in the last bit.
- Clustering: the AMI calculates the expected mutual information with a port of the `lgam` of Cephes and with `Math.exp`. MTEB calls `gammaln` of SciPy and `lgamma` and `exp` of the C library. Thus the AMI can differ from MTEB by about 1e-14.
- Clustering: text only. A task with another modality throws. `AbsTaskClusteringLegacy` calculates the V-measure of each set of inputs. For another modality, MTEB clusters the whole split and also calculates the NMI, the ARI and the cluster accuracy; the port does not. The descriptive statistics, the push to the Hub and `_convert_to_fast` are not ported. A label that is not a string or a number throws. MTEB's `AbsTask` holds `rng_state`. Here only `AbsTaskClustering` holds `rngState`, because only clustering draws from it. `_check_label_distribution` checks that the labels of each row are among the labels of all rows, which is always true. The port keeps only its `TypeError` for a label that is not a string or a list. `MiniBatchKMeans` takes dense float32 data, k-means++, weights of 1 and a `tol` of 0. `RandomState.uniform` takes no bounds: with bounds other than 0 and 1, the C code of numpy can fuse the multiplication and the addition (an FMA on arm64). `sample` and `choices` of `PythonRandom` take `n` for `range(n)`. The `__call__` of `ClusteringEvaluator` is `call`. `BiorxivClusteringS2S` and `BiorxivClusteringS2S.v2` are ported; the other clustering tasks are not.
- L-BFGS-B: `minimizeLbfgsb` (`dependencies/scipy-lbfgsb.ts`) ports `scipy.optimize.minimize` with `method="L-BFGS-B"` and `jac=True`: the driver of `_lbfgsb_py.py` and the C code of `lbfgsb.c`. The C code has the generalized Cauchy point, the subspace minimization, the line search (`dcsrch` and `dcstep`), the stops and the counts. It returns to the driver for each value of f and g; the port calls the function in its place. SciPy calls the BLAS and LAPACK of the platform (`ddot`, `dnrm2`, `dpotrf`, `dtrtrs`). The port adds each dot product in index order (`dependencies/blas.ts`), and it factors and solves as the reference LAPACK does without blocks. Thus x can differ from SciPy in its last bits. `hess_inv`, `callback`, `eps` and finite differences are not ported.
- LogisticRegression: `LogisticRegression` (`dependencies/sklearn-logistic.ts`) ports the model of scikit-learn with the lbfgs solver, the l2 penalty, an intercept and no sample weights, for float32 data. `fit` returns a `FittedLogisticRegression` with `classes`, `coef`, `intercept` and `nIter`, in place of the fitted attributes of the estimator. scikit-learn keeps float32 data in float32: it rounds the coefficients to float32 for `X @ W' + b`, and it calculates the loss and the gradient of each sample in float32. The port rounds the same values. With Accelerate, `sgemm` adds the products in index order, with one fused multiply-add for each product, and the port does the same. For two classes, scikit-learn calls `sgemv`, whose order the port does not copy. Thus for the same coefficients, the loss is equal to the last bit, and so is the gradient of more than two classes on the golden data. The coefficients go through L-BFGS-B, so they can differ in their last bits, and the difference grows with the iterations. On data that did not converge in 100 iterations, the difference was 2% of a coefficient after 100 iterations, and 2 to 6 of 120 predictions changed. `random_state` is not ported: lbfgs draws no random numbers.
- Classification: `AbsTaskClassification` trains its evaluator model (`LogisticRegression` with `max_iter` 100) on `samplesPerLabel` (8) training rows of each label, and predicts the labels of the evaluation split. It does this in `nExperiments` (10) experiments. `undersampleData` selects the training rows of an experiment: a new `RandomState(seed)` shuffles the indices that the previous experiment shuffled, as in MTEB. Thus the port selects the rows of MTEB. The task encodes the union of the selected rows once, then the evaluation split. The scores of an experiment are the accuracy, and the F1, precision and recall with the macro and the weighted average. When the evaluation labels have two classes, `ap` and `ap_weighted` are the average precision of the predicted labels. Else they are null, and their means are NaN. The scores of the task are the means of the experiments, after `scores_per_experiment`.
- Classification: text only. A task with another modality throws. Not ported: the cross validation (`is_cross_validation`, `n_splits` and KFold), the descriptive statistics and the push to the Hub. `undersampleData` takes no experiment number, because MTEB's `_undersample_data` does not read it. A label that is not an int or a string throws. The `__call__` of `SklearnEvaluator` is `call`. `evaluatorModel` is a `ClassifierModel`: its `fit` returns a model that predicts. `Banking77Classification` and `Banking77Classification.v2` are ported; the other classification tasks are not.
- Multilabel classification: `AbsTaskMultilabelClassification` trains its evaluator model (`KNeighborsClassifier` with 5 neighbours) on the training rows of an experiment, and predicts the label set of each row of the evaluation split. `undersampleDataIndices` selects the training rows: `npRng`, MTEB's `default_rng(seed)` of the task (PCG64), shuffles all the indices, and the task takes each row with a label that has fewer than `samplesPerLabel` (8) rows yet. `npRng` goes on from one experiment to the next and from one evaluation to the next, as in MTEB. Thus the port selects the rows of MTEB. The task encodes the union of the selected rows once, in the order of a CPython `set` of the indices (`dependencies/python-set.ts`), then the evaluation split. An evaluation split of more than `maxEvalSamples` (3000) rows keeps that many rows: `multilabelSubsampling` (`abstasks/abstask.ts`, MTEB's `_multilabel_subsampling`) runs the iterative stratification with the label pairs and a `RandomState(seed)`. The scores of an experiment are the subset accuracy, the LRAP of the predicted label sets, the F1 with the macro average over the labels, and MTEB's Hamming score. The scores of the task are the means of the experiments, after `scores_per_experiment`.
- Multilabel classification: `KNeighborsClassifier` (`dependencies/sklearn-neighbors.ts`) finds the neighbours as the `EuclideanArgKmin32` of scikit-learn does: the squared distance in float64 from the norms and the dot product, a max-heap of 5 for each test row, and the sort of the heap. The square root of the squared distance as a float32 is the distance, as a float32. BLAS adds the dot products in another order than the port. The float32 distance hides that difference unless the two values round to two float32 values, so the neighbours and the distances of the fixtures are equal to the last bit. When the test rows are fewer than the training rows, scikit-learn splits the training rows among its threads and merges the heaps of the threads; the port does the same with `os.availableParallelism()` threads. scikit-learn takes `_openmp_effective_n_threads()`: `OMP_NUM_THREADS` when it is set, else the smaller of the OpenMP count and the physical cores, under a cgroup CPU quota. The two counts are equal when the logical cores are the physical cores and no quota or `OMP_NUM_THREADS` applies. Backlog #3460 ports the rest. The number of threads can change which of two rows at the same distance stays a neighbour. For 15 features or fewer and a large training split, scikit-learn uses a KD tree. The KD tree finds the same neighbours, but it can keep another of two rows at the same distance; the port uses the brute force for all inputs.
- Multilabel classification: text only. A task with another modality throws. A task with one label throws the error of MTEB (`y_true and y_score have different shape`), because scikit-learn then predicts a 1-D array. Not ported: the LRAP of an evaluator model that is a `MultiOutputClassifier` (MTEB's default is not), the descriptive statistics and the push to the Hub. In MTEB, `AbsTaskMultilabelClassification` is a subclass of `AbsTaskClassification`. MTEB loads the weights itself. `model` is not an experiment argument; the other keyword arguments with a value are. A search model takes no `model`. The types of `ModelMeta` reject a load without `model` for an encoder, a load with `model` for a search model, and every load for a metadata without a loader. The loader gets the metadata of the model in its options, where MTEB sets it on the model after the loader returns. `embed_dim` (Matryoshka truncation) and `device` are not ported.

- BM25 (`mteb/baseline-bm25s`): English only. MTEB reads the language of the subset from the task metadata, and reads a subset with more than one language as English. This package does the same, and stops the index with an error for a subset in another language. Not ported: the other languages, the stopwords from the document frequency of a token, the `char` tokenizer, a HuggingFace tokenizer and `mteb/baseline-bm25s-subword`, the bm25s methods other than `lucene`, and the keyword arguments other than `k1` and `b`.

When a document outside the `topK` has the score of the last document in it, numpy's `argpartition` has no fixed choice between them; here the document with the lower position in the corpus stays. With `topK` not smaller than the corpus, each document stays.

Their sha256 values: `jsstemmer-3.1.0.tar.gz` `3a2e93de0dff7b91893af85b71b8f54281e933b6b333af8250c3fe5e5f4d069b`, `base-stemmer.js` `bf6f03e1a0d29d9e6e669a3a13069187e4095a8c67251e475f5b6b2102974e26`, `english-stemmer.js` `5cd32ab2f71dde18be28d026e92654f3117aaada83ae67849bd711ca19b3b36e`. `base-stemmer.js` starts with `// @ts-check` and fails `noUncheckedIndexedAccess`, so `tsconfig.snowball.json` compiles the two files without that option, and `tsconfig.lib.json` reads their declarations.

Make a hybrid of your models with `new HybridSearch`. The type of `fusionStrategy` allows only `'rrf'`, `'dbsf'`, `'rsf'` or a function, so the errors of MTEB for another value are not ported. The name of a fusion function is its `name`, as Python uses `__name__`; a function with an empty name is `custom`. A JavaScript arrow function gets the name of the variable or property that it is assigned to. A ValueError of `hybrid_wrappers.py` is a `RangeError` here.
- `instruction_template.format(instruction=...)` replaces `{instruction}` only; Python's `str.format` also reads `{{` and other fields.
- Task metadata: a language code is checked by its shape (three lowercase letters), not against MTEB's table of 7,922 codes; the 223 script codes are checked exactly. A date is `YYYY-MM-DD` or a datetime at midnight; pydantic also takes Unix timestamps. A validation error names the camelCase field.
- Model metadata: `ScoringFunction` is a const object, and `'euclidean'`, `'manhattan'` and `'custom'` are plain strings. A whole float in the experiment arguments gives its integer form in the experiment name (`1.0` is `"1"`). `toDict` writes the `name` of the loader, as MTEB writes its `__name__`. Each ported loader has the name of the loader of MTEB (`q3e_instruct_loader`, `bm25_loader`, `EmbeddingGemma2Wrapper`), so that MTEB finds the loader of a model_meta.json of this package in its registry. `fromDict` always sets the loader to null, because there is no model registry. `hashKey()` and `equals()` stand for `__hash__` and `__eq__`. The training datasets keep their insertion order; in Python a set has no fixed order. Not ported: `load_model`, the Hub constructors and calculations, zero-shot checks, model cards.
- Results: results older than MTEB 1.11.0 do not load, and the pair-classification fix for results older than 1.12.48 is not ported. A result knows its task only through `fromTaskResults` or `validateAndFilterScores(task)`. `joinRevisions` has no registry, so it ranks revisions by MTEB version, then by whether the revision is known. A revision folder without `model_meta.json` has no model metadata. The polars frames, `_to_dataset`, `get_benchmark_result` and the leaderboard cache are not ported.
- Tables: `toDataFrame` returns a `DataFrame` of `dependencies/pandas.ts`, which has the column labels and the rows of the pandas frame after `reset_index`. A MultiIndex column label is an array. `toString` prints an aligned text table with 6 decimals; it is not the repr of pandas. `aggregationFn` is a function of the scores of a cell, NaN included; MTEB also takes the name of a pandas function. Results without scores give an empty table without a warning. MTEB finds `is_public` in its task registry and gives true for a task outside it; this package has no registry, so `is_public` is true for each task. The categorical columns of MTEB change no value and no order, so the port has none. `getAggregatedScores` has no benchmark branch, because the port has no benchmarks.
- Writers of a table: `toCsv`, `toMarkdown` and `toLatex` give the text of `to_csv`, `to_markdown` and `to_latex` with `index=False`. A `DataFrame` has no dtypes, so each writer uses the dtype that `pd.DataFrame(rows, columns=...)` infers for each column: float64, bool, str (pandas 3 infers it for text) or object. The line end of `toCsv` is the line end of the operating system, as pandas uses `os.linesep`. Three parts are not ported. tabulate counts the width of a text with wcwidth when wcwidth is installed; the port counts code points, as tabulate does without wcwidth. tabulate's ANSI escape codes and separating lines are not ported. Styler's limit of 262,144 cells (`styler.render.max_elements`) is not ported. The repr of a text in a markdown header uses the Unicode tables of Node to find printable characters, not the Unicode 15.0 tables of CPython 3.12.
- Experiments in a table: `includeExperiments` of `toDataFrame` and `getAggregatedScores` is not in MTEB. MTEB's `_aggregate_and_pivot` makes a column for each model (and revision), so it averages the experiments of a model with its default run, and `get_aggregated_scores` keeps the last experiment of a model. With `includeExperiments`, a table has an `experiment` column level (wide) or column (long), with `""` for the default run, as in `join_revisions`. The means are by model and experiment. Each experiment has the scores that MTEB gives for the results of that experiment alone. pandas picks the way to calculate a group mean from all the rows of the table (see Means of a table), so a score can differ in its last bit from the table of that experiment alone. Without the option, the tables and the means are those of MTEB.
- Scores in a table: `scores` of `toDataFrame` is not in MTEB. MTEB's tables read the main score only. With `scores`, the port makes the table of each score as MTEB makes the table of the main score, and puts the tables side by side in the given order. A long table has a column for each score, with the name of the score, in place of `score`. A wide table has a column level for each score, above the models, and the rows of all the tables; a cell that the table of a score does not have is NaN. The port does not make one `pivot_table` with several values: pandas would sort the scores, keep a row while one of its scores is not NaN, and pick the way to calculate each mean from the rows of all the scores (see Means of a table). Thus each score has the table of MTEB to the last bit. A score that no result has gives a `RangeError`. Without the option, the tables are those of MTEB.
- Experiment arguments of a hybrid: MTEB's `HybridSearch` makes its metadata with `ModelMeta.create_empty` and no experiment arguments, so two hybrids of the same models with other settings have one name and one cached result, and `evaluate` reads the first result for the second hybrid. Here the settings that are not the defaults are its experiment arguments: `sub_models` (the experiment name of each model, or `None`), `weights` (when given), `rrf_k` (with `'rrf'` and an `rrfK` that is not 60) and `sub_model_top_k` (when given). A hybrid with all the default settings has no experiment arguments, as in MTEB.
- Means of a table: pandas 3.1.0 calculates a group mean in one of two ways (`BaseGrouper._cython_operation`). When the group number of each row never decreases and no score is NaN, it divides `np.add.reduceat` of each group by its size. Else it uses the Kahan summation of `group_mean` (`_libs/groupby.pyx`). The port does the same, so the two ways can give different last bits for the same scores, as in pandas. `Mean(Task)` and `Mean(TaskType)` add numpy float64 values with Python's `sum`, which adds a float subclass without compensation, so the port adds them in a plain loop.
- Result files: a whole float is written as an integer (`1`, not `1.0`), and a date has milliseconds, not microseconds. `run_settings.jsonl` records the version of MTEB only. MTEB loads `model_meta.json` without validation; this package validates it. Cache listings are sorted; Python keeps the order of the file system.
- MTEB treats a result folder as an experiment when any part of its absolute path is `experiments` (`"experiments" in path.parts`). So a cache below a folder such as `~/Desktop/experiments` reads its results as experiments. This package looks for `experiments` only in the folder layout below `results/`.
- The predictions file (`<task name>_predictions.json`): MTEB writes it with `json.dump` and reads it with `json.load`, so the documents of each query stay in the order of the search. A JavaScript object moves integer-like ids such as `"10"` to the front, and when scores are equal at the `topK` cut or at the first result, the order selects the documents. Thus this package writes the file with `pythonJsonDumps` (`results/json.ts`), with the separators of Python, and reads it in the order of the file with `jsonLoadsInOrder`, which uses `visit` of jsonc-parser 3.3.1. Both read and write the `NaN`, `Infinity` and `-Infinity` tokens of Python's `json` module, as MTEB does.
- pytrec_eval keeps the relevance of the last query in a static cache (`form_res_rels.c`). When one call ends with the query id that the next call starts with, the next call reads the old relevance. This package computes each call again. For a query whose judgments are all negative, trec_eval keeps the number of relevance levels of the query before it; here such a query has no levels.

## Not from MTEB

MTEB has no significance test. The modules in `src/significance/` are not a port, and they have no Python source module in MTEB. A change in MTEB does not change them.

- `significance/per-query-scores.ts` (`perQueryScores`): the value of a score for each query, from the predictions file that `evaluate` writes. It calls `calculateRetrievalScores` of `evaluators/retrieval-metrics.ts`, and does not export it. The predictions file holds only the queries that the evaluation scored (the queries with a relevant document), and `perQueryScores` applies `ignoreIdenticalIds` and `skipFirstResult`, as `AbsTaskRetrieval` does, so the mean of the values, rounded to 5 digits, is the score in the result. `abstasks/retrieval.ts` exports its reader of the predictions file (`readPredictionsFile`) for it.
- `significance/paired-bootstrap.ts` (`pairedBootstrapTest`): the paired bootstrap test over queries (Efron and Tibshirani 1993; Sakai 2006 for retrieval). The replicates are those of `numpy.random.default_rng(seed)`, the means are NumPy means, and the interval is `np.percentile(..., [2.5, 97.5])`. Thus a verdict is the verdict of the same test in NumPy, to the last bit. `p` is `min(1, 2 * min(np.mean(means <= 0), np.mean(means >= 0)))` of the same replicate means, the two-sided percentile-bootstrap p-value (Efron and Tibshirani 1993).
- `significance/holm.ts` (`holm`): the Holm adjusted p-values (Holm 1979). It sorts the p-values, multiplies the k-th smallest of n by n - k + 1, takes the running maximum, caps each value at 1, and gives the values in the input order. These are the values of `statsmodels.stats.multitest.multipletests(pvals, method="holm")[1]` of statsmodels 0.15.0, to the last bit. Equal p-values get equal adjusted values, as in statsmodels, whatever the order of the sort.

The test and its generator are copies of code from other packages of this repository. See [copied-code.md](./copied-code.md).

MTEB has no report either: its leaderboard compares models over many tasks. `src/report/` (the subpath `@zukhruf/mteb/report`) is not a port, and a change in MTEB does not change it.

- `report/report.ts` (`Report`): `Report.from` reads the results of a task with `loadResults`, the main score of each query with `perQueryScores`, and the queries and qrels of the task, for each split and subset. It gives a page (`toHtml`), the two tables as Markdown (`toMarkdown`), and the tables `scores` (`toDataFrame` at the split level, or the subset level for a task with more than one subset) and `verdicts`. The score of each query is the main score, or nDCG@10 when `perQueryScores` has no value of the main score for each query (MRR). A recall at a cut-off above the size of the corpus is 1 for each model, so the tables and the page leave it out. A model without predictions, a model without a result and a baseline that is not one of the models are errors.
- `report/verdicts.ts` (`verdicts`, `decide`): a `pairedBootstrapTest` for each comparison and tested score; `holm` corrects the p-values of all the comparisons but the primary one, which is tested alone; a difference counts when its deciding p-value is below 0.05.
- `report/page.ts`, `styles.ts`, `script.ts`: one HTML page without `<html>`, `<head>` or `<body>`, with its CSS and script inline and the IBM Plex fonts of Google Fonts. The page uses the words of this package (query, document, baseline) and the model names of the results.

## Copies inside this package

Two pydantic rules have two copies each: the alias of a field (`eval_langs` to `evalLangs`) is the function `camelCase` in `abstasks/task-metadata.ts` and `models/model-meta.ts`, and a pydantic `float` (a number that can be NaN or infinite) is the schema `float` in `models/model-meta.ts` and `results/task-result.ts`. The copies are the same. By the Rule of Three, a third place that needs it moves it to `dependencies/`, with both copies (backlog #3241). Until then, change both.

`PairClassificationEvaluator` and `AnySTSEvaluator` each encode a column of texts with the same steps (`#encode`): the check of the modality and of the column, then a dataloader of the texts. MTEB has the same two copies, in `pair_classification_evaluator.py` and `any_sts_evaluator.py`. A third evaluator that needs these steps moves them to `evaluators/`. Until then, change both.

`dependencies/python-random.ts` and the `RandomState` of `dependencies/numpy-random.ts` each have a copy of the MT19937 generator: the twist and the tempering. CPython and numpy have the same two copies. The seeding is different: CPython calls `init_by_array` with the 32-bit words of the seed, and numpy calls `init_genrand` with the seed. A third MT19937 moves the generator to its own module. Until then, change both.

`NumpyGenerator` and `RandomState` of `dependencies/numpy-random.ts` each have a copy of `random_interval` of numpy's `distributions.c` (`#interval`): masked rejection on 32-bit draws. NumPy has one function that takes the bit generator. `NumpyGenerator.shuffle` of a list calls it with PCG64, and `RandomState.shuffle` with MT19937. A third place that needs it moves it to one function that takes the 32-bit draw. Until then, change both.
