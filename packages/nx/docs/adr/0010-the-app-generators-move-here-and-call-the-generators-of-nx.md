# The app generators move here and call the generators of Nx

Status: Accepted 2026-11-18 by the owner (backlog #3338), with decision 1 changed: the generated web app keeps the theme script and the `dark` variant of the monorepo standard §10.

factory writes its apps with 4 generators of its private package `@factory/foundation` (`tools/foundation/src/generators`): `node-app` (Hono on `@hono/node-server`, evlog, terminus, a zod env, one ESM esbuild bundle, a Dockerfile, an sdk-it client), `react-app` (React Router 8 in data mode on Vite, Tailwind, the React Compiler, Vitest), `pair` (the client in the web, the SPA served by the api and put in its image) and `ui-package` (a Vite library with types). whatisgoingon copied them by hand on 2026-10-29, text2sql is the ancestor, and deepagents holds a part. meddit is the third repo of the same app kinds, so they move here (#3338). ADR 0009 moved the root files first and listed in "What only an app generator writes" the wiring that is now these generators'.

The audit of 2026-11-18 (#3338) found these gaps in factory's generators: the image does not know its commit; the `@nx/vitest` plugin runs `vitest` in watch mode; `@nx/vitest` adds `^build` to `test.dependsOn`; the pins are old (Nx 24.0.1, Vitest 4); the brand of factory is in the code (the `@factory` scope fallback, the `.factory` portless domain, Factory in schemas, descriptions, errors and comments); the react-app tsconfig writes to `dist` (#3268 item 4); and the `ui.route.ts` comment stops mid-sentence and names text2sql (#3268 item 5).

Nx gives these facts (24.0.6 published source, 23.2.1 in zukhruf, read on 2026-11-18):

- In a TS solution workspace, `@nx/node`, `@nx/react` and `@nx/vitest` 24.0.6 default `useProjectJson` to false, so the targets go to the `nx` key of the project's `package.json` and no `project.json` is written (`@nx/node/dist/src/generators/application/lib/normalize-options.js:43`, `create-project.js:67-80`). factory reads `project.json`, which 24.0.6 does not write.
- The public `configurationGenerator` of `@nx/vitest` sets `addPlugin: false` unless the caller passes it (`@nx/vitest/dist/src/generators/configuration/configuration.js:53`). Without the plugin, it writes a target with the `@nx/vitest:test` executor, and the project's own `test` target replaced it in factory's code.
- In a TS solution workspace, `configurationGenerator` adds `^build` to the `test` target default (`configuration.js:180-187`).
- `ensurePackage(pkg, version)` of `@nx/devkit` resolves a package from the workspace root, and else installs it into a temporary folder and adds it to the paths of `require` (`@nx/devkit/dist/src/utils/package-json.js:429-480`). The Nx generators load their own plugins this way.
- `@nx/vitest` 23.2.1 accepts Vitest 3 and 4 only (`assertSupportedVitestVersion`); 24.0.6 accepts Vitest 5.
- `@nx/js/tsx`, which infers `serve` from the `// @nx-target-name: serve` header, exists only in Nx 24 (`@nx/node/dist/src/generators/application/lib/add-script-serve.js`).

## Decision

The package gets 4 more generators in `generators.json`: `node-app`, `react-app`, `pair` and `ui-package`. The README sections after `## generators` give the files and keys that each writes.

1. **The 4 generators move with their behavior, and the brand stays in factory.** The scope comes from `workspaceScope`, which stops for a name with no scope: the client is `@<scope>/<app>-client`, and the portless domain is `<app>.<scope>` (ADR 0009, decision 5). The schemas, the descriptions, the errors of `pair` and the comments name no product. The fonts, the colors and the favicons of factory stay in factory, and the generated `index.html` has none of them. The theme script is not brand: the monorepo standard §10 puts it in every web app, so the generated `index.html` keeps a script with no colors that sets the `light` or `dark` class before the first paint (the stored choice, or the system's), and `styles.css` keeps `@custom-variant dark (&:is(.dark, .dark *))`. The first proposal dropped both as brand; the owner kept them on 2026-11-18.
2. **An app generator calls the generator of Nx for its kind, and loads it at run time.** `node-app` calls `@nx/node`, `react-app` calls `@nx/react` and `@nx/vitest`, and `ui-package` calls `@nx/react`, as factory does. `nxPlugin(entry)` requires the plugin from this package, and else calls `ensurePackage(name, nxVersion)`. So `@nx/node`, `@nx/react`, `@nx/vite` and `@nx/vitest` are optional peers of `@zukhruf/nx`, and a repo with only a backend installs no React plugin (ADR 0009, decision 6). The plugin's own generator adds it to the root `package.json`, and the app generator sets it to `nxVersion`.
3. **Each call passes `useProjectJson: false` and `addPlugin: true`.** The targets are in the project's `package.json` in Nx 23 and 24 alike, as whatisgoingon has them, and the inferred plugins (`@nx/vite/plugin`, `@nx/vitest`) give the targets, not the old executors. `react-app` then sets `testMode: 'run'` on the `@nx/vitest` entry (#3338).
4. **Each app generator runs `init` first**, as factory's ran its `workspace` generator. The Nx generators read the root files of the standard (`tsconfig.base.json`, the solution `tsconfig.json`, `workspaces`) to choose the TS solution setup. Its install callback runs before the app's.
5. **The gaps of the audit are closed in the generated code** (#3338): the Dockerfile has `ARG BUILD_SHA` and `ENV BUILD_SHA=$BUILD_SHA` in the runtime stage, `env.ts` has `BUILD_SHA: z.string().min(1).optional()`, `/api/healthz` returns `{ status: 'ok', sha }` with `null` outside an image, and `docker:build` passes `--build-arg BUILD_SHA=$(git rev-parse HEAD)`, as whatisgoingon does; the `test` target default stays as it was before `@nx/vitest` ran, so it is `["...", "^sdk"]` after `node-app`; the react-app tsconfig writes to `out-tsc`; the `ui.route.ts` comment is whole. `@godaddy/terminus` stays (the owner declined `@zukhruf/shutdown`, #3338).
6. **The wiring of one kind of app is in its generator, as ADR 0009 decision 6 lists it.** `node-app` writes the `@nx/esbuild:esbuild` default, `^sdk`, the sdk-it exclusion of `production`, `generators["@nx/node"]`, the `hono` config and the env settings and the sdk-it `allowDefaultProject` in the project config. `react-app` writes the Tailwind sync generator, `prettier-plugin-tailwindcss` in `.prettierrc`, `generators["@nx/react"]`, and `@zukhruf/eslint/react` with the `react-router` and `tailwind` configs in the project config. The generator defaults are merged option by option, so a default that the Nx plugin wrote a moment before stays and the missing options are added.
7. **The content of each written file is a string in a `.ts` module** (ADR 0009, decision 8). factory's EJS templates become functions.
8. **Root packages: a missing one gets its pin, a version that was there stays, and residue that the run added goes.** The generator reads the root package names before the Nx generator runs. After it, each package of the app's list that was not there gets its exact version from `appPackageVersions` (the latest on 2026-11-18), also over the version that the Nx generator wrote; each residue name that the run added goes; and each `nx` and `@nx/*` gets `nxVersion`. The residue is factory's (`@swc/*`; `eslint-plugin-import`, `eslint-plugin-jsx-a11y` and `eslint-plugin-react`, which cap ESLint below 10; for ui-package `@babel/core`, `@babel/preset-react`, `ajv`, `vite-plugin-dts`), and 3 more: the root `react` and `react-dom` that `@nx/react` adds (each project declares its own, as in whatisgoingon), and `@vitest/ui` (no target runs it). `@types/node` and `tslib` get exact versions. `node-app` names `esbuild: true`, and `@parcel/watcher: false` and `fsevents: false`, which `@nx/node` brings and whose scripts `strict-allow-scripts=true` stopped in the smoke test. Two `overrides` are added when missing: `@juristr/nx-tailwind-sync` takes the one `@nx/devkit` (#4532), and `@sdk-it/cli` and `@sdk-it/hono` take the root `typescript` (`$typescript`), because sdk-it 0.46.11 peers on `^6.0.3` and the TypeScript 6 API alias is 6.0.2, the last `@typescript/typescript6`; whatisgoingon has the same 2 edges.
9. **The tests run on a virtual Tree with Nx 23.2.1.** zukhruf's root installs `@nx/node`, `@nx/react`, `@nx/vite` and `@nx/vitest` 23.2.1 as devDependencies (`manifest/nx-family-pinned` refuses them in a package), names `@parcel/watcher: false` in `allowScripts`, and overrides the optional `express` peer of `@nx/react` 23.2.1 to 5.3.0, so npm keeps express 5 at the root. The smoke test runs the generators under create-nx-workspace and Nx 24.0.6.
10. **The Vitest config of `react-app` sets `testTimeout: 300_000`** (#4758). 300 s is zukhruf's test limit, the minimum of `zukhruf/no-short-test-timeout` and the default of `@zukhruf/nx/test`. Vitest's default of 5 s failed meddit's auth tests on CI, which sign users up and in against a real better-auth server whose scrypt hashing is slow on a runner (meddit 69f53b2).

## Considered Options

- **Write the project files directly, with no generator of Nx.** Not selected. factory's generators replace most of what `@nx/node` and `@nx/react` write and then delete residue, so this would own less glue. But it is a redesign, not a move, and the README table of ADR 0009 names the Nx plugins as the wiring of these generators. It stays open for a later item.
- **`@nx/node`, `@nx/react` and `@nx/vitest` as dependencies of `@zukhruf/nx`.** REJECTED. A repo with only a backend would install React, Vite and Vitest plugins (ADR 0009, decision 6).
- **Call `ensurePackage` alone.** REJECTED. It resolves from the workspace root and from the folder of `@nx/devkit`, not from this package, so a plugin that npm nests here is not found and is installed again.
- **Read `project.json`, as factory does.** REJECTED. Nx 24.0.6 does not write it in a TS solution workspace.
- **Delete `^build` from the `test` default after `@nx/vitest`.** REJECTED. It would also delete a `^build` that the repo wrote on purpose. The default before the call is restored instead.
- **Port `tests/modern-node.test.ts` and `tests/root-vite.test.ts`.** REJECTED. They write the workspace to disk and run ESLint, or read a plugin that is installed in the repo; zukhruf's installed versions are not the generated ones. The smoke test runs lint and `npm install` with strict peers on the generated repo instead.
- **Override the TypeScript 6 alias to 6.0.3 in `init`.** REJECTED. `@typescript/typescript6` has no 6.0.3.

## Consequences

- meddit gets a backend and a web app from npm with 3 commands after the preset. factory, whatisgoingon and text2sql can delete their copies (C1 #4611 and the other migrations).
- An image built without `--build-arg BUILD_SHA` gets `BUILD_SHA=""`, and `env.ts` stops it at start. `docker:build` always passes it.
- The tests cover what these generators write, on Nx 23.2.1. What `@nx/node` and `@nx/react` 24.0.6 write themselves (the `@nx/js/tsx` serve target, the inferred Vite targets) is proven only by the smoke test.
- `react-app` cannot run twice under Nx 23.2.1, because its first run pins Vitest 5, which `@nx/vitest` 23.2.1 refuses. Nx 24 accepts it.
- The project name is the package name, `@<scope>/<app>`, so a target runs as `nx run @acme/backend:docker:build`.
- The image installs from the lockfile with `npm ci`, so a `@zukhruf/nx` from a `file:` tarball or an `npm link` breaks `docker:build`. A repo that builds its image takes `@zukhruf/nx` from the registry.
- The smoke test of 2026-11-18 (Nx 24.0.6, an `npm pack` tarball): preset in a folder with only `git init`, `node-app apps/backend`, `react-app apps/web`, `pair`, `npm install`, `nx sync`, and `nx run-many -t typecheck lint test build` passed for the 3 projects; the first commit passed each hook; `@acme/backend:docker:build` built the image, and its `/api/healthz` returned the `git rev-parse HEAD` of the commit. It found 3 gaps that the generators now close: the sdk-it `typescript` peer, the 2 install scripts, and `.prettierrc`, which `react-app` now writes after `formatFiles` and formats itself, because Prettier loads each plugin of the file and `prettier-plugin-tailwindcss` is installed only by the callback.
- `CONTEXT.md` gets app generator, pair, generated client, build sha and residue.
