# The prisma generator writes a Postgres db package and wires a backend

Status: Proposed 2026-11-18 (backlog #4604). Decisions 1 to 8 restate the design of #4604, ADR 0008, ADR 0009 and ADR 0010, and are accepted with them. Decisions 9 to 15 are new and wait for the owner.

Six projects hold a Prisma db package of the same shape: `packages/persistence/db`, `apps/v2/db`, `apps/authx/db`, `apps/desktop/db` (sqlite) and `tools/playground/amail` of text2sql, and `packages/persistence/db` of factory. Three `Dockerfile.migration` copies in text2sql (`apps/v2`, `apps/authx`, `apps/backend`) are the same except for the package name and path. meddit needs a seventh, so the shape moves here (#4604). The design of #4604 (2026-11-18) lists what is shared as is and decides each difference. `@zukhruf/nx/prisma` gives the targets (#3339, ADR 0008).

Facts read on 2026-11-18:

- The `latest` tag of `prisma` on npm is `8.0.0-rc.34`, and the `latest` of `@prisma/client` and `@prisma/adapter-pg` is `7.10.1` (`npm view <name> dist-tags`).
- `@prisma/engines` 7.10.1 has a `postinstall` (it downloads the schema engine), and `prisma` 7.10.1 has a `preinstall`; `@prisma/client` and `@prisma/adapter-pg` have none. `@zukhruf/testing` brings `ssh2`, whose `install` and the one of `cpu-features` stopped `npm install` under `strict-allow-scripts=true` in the smoke test.
- `PrismaClient.$connect()` on `@prisma/adapter-pg` opens no connection. A backend that awaited it served with 0 sessions in `pg_stat_activity`, and with a wrong password it started and served. One `SELECT 1` opened a session, and with a wrong password the process stopped with `password authentication failed`.
- typescript-eslint 8 builds one project service for the process, from the parser options of the first file it parses (`TSSERVER_PROJECT_SERVICE ??=` in `typescript-estree/dist/parseSettings/createParseSettings.js`). A block with `files: ['sdk-it.config.ts']` and its own `allowDefaultProject` passed or failed by the order of the files: 1 of 3 runs of `eslint .` in a generated backend failed.
- `@nx/node` writes no `projectType` into the `nx` key of `package.json`. `nx show project` gives none, so `manifest/dependency-checks` of `@zukhruf/eslint` takes a backend for a library and asks it to declare each workspace package it imports. `prune-lockfile` then writes the db package as `file:./workspace_modules/...`, which the runtime image cannot install.

## Decision

The package gets the generator `prisma` in `generators.json`. The README section `## prisma generator` gives the files.

1. **The shared parts are written as they are** (#4604 SHARED AS IS): `schema.prisma` with `provider = "prisma-client"`, `output = "src/prisma"`, `importFileExtension = "ts"` and `provider = "postgresql"`; models in `models/*.prisma`; `prisma.config.ts` with `schema: '.'`, `migrations.path`, and the two URLs read only when set; the `development`/`types`/`import`/`default` exports; `@prisma/engines: true` and `prisma: false` in `allowScripts`; `Dockerfile.migration` with the package name and root as its parameters.
2. **No dotenv, and the URL is `CONNECTION_STRING`** with an optional `SHADOW_CONNECTION_STRING` (#4604). Nx loads the project `.env` into each task; the migration container gets the variable from its environment.
3. **`createPrisma({ connectionString })` of factory is the client module**, with `export *` of the generated client. It reads no environment and opens no pool at import. text2sql's pool tuning, pool error logging, `$extends` and `omit` stay with each consumer (#4604).
4. **`@prisma/client` and `@prisma/adapter-pg` are in `dependencies`, the `prisma` CLI in `devDependencies`** of the package, where `npm ci --workspace` of the image finds it (#4604).
5. **The three Prisma packages have one exact stable version, 7.10.1, in `appPackageVersions`**, never the `latest` tag, and a test checks that the written versions are equal and stable (#4604, VERSION GOTCHA).
6. **The generator writes no target, and it adds `generate` to `targetDefaults.typecheck.dependsOn` and `targetDefaults.build.dependsOn`, with `...`**, and lists `@zukhruf/nx/prisma` in `nx.json` (#3339, ADR 0008; ADR 0009 decision 6: wiring that one kind of project needs belongs to its generator). The generator block sets `output`, so `generate` is cached.
7. **`src/testing.ts`, exported as `./testing`, gives `applySchema(connectionString)`**: it runs each `migrations/*/migration.sql` in order with `pg`, with no `_prisma_migrations` record (the Postgres twin of text2sql `apps/desktop/db/src/testing.ts`). The test takes a database from `@zukhruf/testing/postgres` with `await using`, and the project has the tag `test:docker` (#4604).
8. **`backend` wires a node-app** (#4604): `env.ts` declares `CONNECTION_STRING: z.string().min(1)`, `.env.example` gets the key, `startup.ts` creates the client before the app serves, terminus `onSignal` disconnects it, and the backend gets the database test and the tag `test:docker`. `/api/healthz` stays as it is. The generator runs `init` first (ADR 0010 decision 4), and each file is a string in a `.ts` module (ADR 0009 decision 8).
9. **The generator writes the files itself and calls no generator of Nx.** No Nx generator writes a Prisma package, and `@nx/js:library` would add a test runner, a README and a build that the package replaces.
10. **The build is the `tsc --build` of `tsconfig.lib.json` that `@nx/js/typescript` infers, with `emitDeclarationOnly: false` and `rewriteRelativeImportExtensions: true`.** The test of a consumer imports the package through `dist`, and the generated client imports its files with `.ts`. text2sql writes the declarations with tsc and the JavaScript with a second esbuild target; one tsc build does both. The package also gets `tslib`, because the base sets `importHelpers`, and `pg` and `@types/pg` for `applySchema`.
11. **The db package always has its own test, and a wired backend gets one more.** The package test imports `./index.ts` and `./testing.ts`, so a workspace with no backend proves its migrations and client. The backend test imports `@<scope>/<db>` and `@<scope>/<db>/testing`, so it proves the exports and the build that the backend consumes.
12. **`startup.ts` awaits one `SELECT 1`, not `$connect()`.** `$connect()` opens no connection on a driver adapter (the facts above), so a wrong `CONNECTION_STRING` would start a backend that fails on its first query. The query is the cheap real operation (EAFP).
13. **The backend declares the npm packages of the db package, not the db package.** The esbuild bundle inlines the workspace package and leaves `@prisma/adapter-pg`, `@prisma/client`, `pg` and `tslib` external, so the deploy manifest and `prune-lockfile` need them, and `manifest/dependency-checks` of a bundled app asks for them. node-app now writes `projectType: "application"`, which `@nx/node` leaves out; without it the lint asks for the workspace package and the image cannot install it (the facts above).
14. **The `allowDefaultProject` block of a project config takes `**/*.ts`, as the root block does.** One project service serves the process, so the block must be the same for each file it can parse first. This changes node-app's block too, whose `files: ['sdk-it.config.ts']` passed by the order of the files.
15. **The generator adds the rest that the package needs to the root:** `<root>/src/prisma` to `.gitignore` and `.prettierignore` (the client is not committed and not formatted), `models/.gitkeep` (the image copies `models/`), `.dockerignore` when missing (else `COPY --parents **/package.json` copies `node_modules`), the package root in `workspaces` when no `<parent>/*` glob holds it, `@zukhruf/testing` at the zukhruf version, and `ssh2: false` and `cpu-features: false` in `allowScripts`, as zukhruf, factory and text2sql have them. A second run keeps the files of the package and adds no line or key twice.

## Considered Options

- **A test only in the backend, as the design of #4604 words it.** Not selected. A db package with no backend would have no test of `applySchema` or of the client (decision 11).
- **The backend depends on `"@<scope>/db": "*"`.** REJECTED. `prune-lockfile` writes it as a `file:` workspace module, and the runtime image runs `npm ci --omit=dev` with no workspace modules (decision 13).
- **`await prisma.$connect()` in `startup.ts`, as the design of #4604 words it.** REJECTED by the smoke test (decision 12).
- **An esbuild bundle of the package, as factory and text2sql do.** Not selected (decision 10). It needs a second target for the declarations, and the backend bundles the package anyway.
- **`**/src/prisma` in the root files of `init`, as `.sdk-it` is there.** Not selected. The generator knows the root, so the line names it.
- **A first model and migration.** REJECTED. No copy starts with one, and each consumer would delete it. The first migration is the consumer's.
- **An `importPath` option.** Not selected (strike 1). The name is `@<scope>/<last segment>`, as for node-app; text2sql's `apps/v2/db` and `apps/authx/db` would need it when they migrate.

## Consequences

- meddit gets its db package with one command after node-app: `nx g @zukhruf/nx:prisma packages/db --backend apps/backend`. The dokploy generator (#4603) takes its `Dockerfile.migration` for the one-shot migrate service.
- Migrations are written by hand or with `prisma migrate diff`, and applied with the `deploy` target or the image. `migrate dev` needs a TTY, and no target runs `migrate reset` on a shared database (text2sql memory).
- The backend stops at start when the database refuses it, so a compose must start Postgres and the migrate service first, as the dokploy compose does.
- The smoke test of 2026-11-18 (Nx 24.0.6, an `npm pack` tarball): preset in a folder with only `git init`, `node-app apps/backend`, `prisma packages/db --backend apps/backend`, `npm install`, `nx sync`, `nx run @acme/db:generate`, and `nx run-many -t typecheck lint test build` passed for the 3 projects; both database tests ran against Postgres of `@zukhruf/testing`. With a first migration, `Dockerfile.migration` built, and its container applied `20261118000000_init` to a new `postgres:18-alpine`. The backend image served `/api/healthz` with one database session, exited 0 on SIGTERM, and with a wrong password stopped with `password authentication failed`. It found the 5 gaps that decisions 12 to 15 close.
- `CONTEXT.md` gets db package and schema replay.
