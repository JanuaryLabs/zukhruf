# A query is a string or a query bundle, with a text for each kind of search

Status: Accepted 2026-11-25 (backlog #5579, #5580).

Decision-makers: the meddit session meddit-7a, which decided each question from the leader tables of `paper-v2.md` and `leaders-broad.md` (see Confirmation). Ezz set the method: "I want to follow the leaders" (2026-11-24, after he did not approve the first paper, whose names came from no leader). He ruled that `MultiQueryRetriever` is not shaped around the limits of one host's source: "we should not design around pubmed limit. zukhruf is std package" (2026-11-24). On 2026-11-25 he gave the go: "Go: build both, commit each".

The port took one string ([ADR 0002](./0002-a-retriever-is-a-port-for-any-source.md)). It did two jobs. It was the information need, which `Rerank`, `MaximalMarginalRelevance` and the language models of `HydeRetriever` and `MultiQueryRetriever` read. It was also the text that each search matches. A keyword retriever joins every word with AND by default ([ADR 0004](./0004-a-keyword-retriever-queries-the-keyword-index-that-elt-writes.md)), and a live source can have its own syntax (ADR 0002). So a reranker over such a source ranked against the source's syntax (#5579), `HydeRetriever` over a reranking stack gave the reranker the model's passage, and `FusionRetriever` gave every child the same string (#5580).

The leaders give each search a text of its own: eight of nine. LangChain alone sends one string to every child ([ensemble.ts](https://raw.githubusercontent.com/langchain-ai/langchainjs/main/libs/langchain-classic/src/retrievers/ensemble.ts)). Five address a node of the request: Elasticsearch's child retrievers ([rrf retriever](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/retrievers/rrf-retriever)), Qdrant's `prefetch` ([hybrid queries](https://qdrant.tech/documentation/search/hybrid-queries/)), OpenSearch's `hybrid.queries` ([hybrid query](https://docs.opensearch.org/latest/query-dsl/compound/hybrid/)), Vespa's YQL operators ([hybrid search tutorial](https://docs.vespa.ai/en/learn/tutorials/hybrid-search.html)) and Haystack's inputs per component ([tutorial 33](https://haystack.deepset.ai/tutorials/33_hybrid_retrieval)). Three address a kind of search: LlamaIndex's `QueryBundle` with `query_str` and `custom_embedding_strs` ([schema.py](https://raw.githubusercontent.com/run-llama/llama_index/main/llama-index-core/llama_index/core/schema.py)), .NET's `HybridSearchAsync(searchValue, keywords, …)` ([IKeywordHybridSearchable.cs](https://raw.githubusercontent.com/dotnet/extensions/main/src/Libraries/Microsoft.Extensions.VectorData.Abstractions/IKeywordHybridSearchable.cs)) and Weaviate's `hybrid(query, vector)` ([hybrid search](https://docs.weaviate.io/weaviate/search/hybrid)). Over 34 packages with a request that runs several searches, 23 give each search its own text; the address ties three ways, 11 by kind, 11 by node and 11 one string (`leaders-broad.md`, section 3).

## Decision

- `type QueryBundle = { readonly query: string; readonly keywords?: readonly [string, ...string[]]; readonly customEmbeddings?: readonly [string, ...string[]] }` and `type QueryType = string | QueryBundle`, after LlamaIndex.TS (`@llamaindex/core` 0.6.22, `query-engine/dist/index.d.ts`: `type QueryBundle = { query: MessageContent; customEmbeddings?: string[]; embeddings?: number[] }`, `type QueryType = string | QueryBundle`).
  - `query` is the information need, the leaders' majority name. `Rerank` and `MaximalMarginalRelevance` read it, the models of `HydeRetriever` and `MultiQueryRetriever` read it, and so does every search that has no text of its own.
  - `keywords` is what a keyword retriever matches: it quotes each word of each keyword, and the words of `query` when `keywords` is absent. It is a list, as .NET's `ICollection<string> keywords`.
  - `customEmbeddings` is what an embedding retriever embeds: it embeds each text and searches with the mean of their vectors, as LlamaIndex's vector retriever takes `mean_agg` of its `embedding_strs` and Haystack's HyDE recipe averages its embeddings. It embeds `query` when `customEmbeddings` is absent, as LlamaIndex's `embedding_strs` gives `[query_str]`. The name is LlamaIndex.TS's; the Python LlamaIndex writes `custom_embedding_strs`.
  - Both lists are non-empty: an empty list is no search, and LlamaIndex's `mean_agg` refuses one.
  - A string is a bundle with only `query`, as LlamaIndex's `retrieve` makes `QueryBundle(str)`. A plain string stays valid wherever no field of a host is required; `keywords` and `customEmbeddings` are optional overrides.
- The port is `interface Retriever<in Q extends QueryType = QueryType> { readonly retrieve: (query: Q, options?: RetrieveOptions) => Promise<ScoredPassage[]> }`. A host adapter declares its own fields in its own bundle type, `QueryBundle & { readonly jql: string }`, as a Haystack component declares its own inputs. Such a retriever takes no string.
- The port is a function-typed property, not a method: TypeScript checks the parameter of a method both ways, so a retriever that needs `jql` would pass as a plain one. A class still writes `async retrieve(…)` as a method, so each composite class also declares `in Q`: declaration emit writes a private field as `#private` without its type, and without the annotation the `Q` of the published `FusionRetriever` and `PostprocessingRetriever` checks both ways, so a host-typed composite would widen to a plain one (#5637; `type-tests/published-types.ts` proves it against `dist`).
- `BatchRetriever.retrieveMany` takes `readonly QueryType[]`, and embeds the texts of every query in one `embedMany` call.
- `Postprocessor` does not change. Its `query` is the information need, a string, as the leaders' rerankers take a string: Elasticsearch `inference_text`, OpenSearch `query_text`, Weaviate `rerank.query`, Haystack `query`, the AI SDK's `rerank({ query })`.
- What each composite passes down:
  - `FusionRetriever<Q>` passes the query unchanged to each child, as LlamaIndex's `QueryFusionRetriever` gives each retriever the same bundle. Its query type `Q` is one that each child takes. TypeScript infers the narrowest query type of the children, so a fusion of plain retrievers and one host adapter takes the host's bundle. Two children that need two other fields take `new FusionRetriever<A & B>(…)`.
  - `PostprocessingRetriever<Q>` passes the query to its retriever and `query` to each postprocessor.
  - `HydeRetriever` asks its model with `query` and passes the bundle with `customEmbeddings: [passage]`. `query` and `keywords` stay. The three leaders with HyDE give the passage to the embedding search only: LlamaIndex's embedding retrievers alone read `custom_embedding_strs`, and Haystack's HyDE recipe feeds the embedder only. So its retriever is a `Retriever<QueryBundle>`, as the one of `MultiQueryRetriever` is a `Retriever<QueryType>`. A retriever of strings only, or a host source that needs its own field, does not compile under it. A host fuses its source beside HyDE: `new FusionRetriever({ retrievers: [issues, new HydeRetriever({ retriever: embeddings, model })] })`. The fusion gives the host its bundle, and HyDE gives the passage to the embedding search only, which is also the more precise composition.
  - The passage replaces the caller's `customEmbeddings`, so the embedding search reads the passage alone, as ADR 0008 accepted. LangChain's `HydeRetriever` searches its vector store with the answer alone ([hyde.ts](https://raw.githubusercontent.com/langchain-ai/langchainjs/main/libs/langchain-classic/src/retrievers/hyde.ts), `sources/lc-hyde.ts:96-115`), and Haystack's HyDE recipe averages the embeddings of the made-up passages alone ([HyDE](https://docs.haystack.deepset.ai/docs/hypothetical-document-embeddings-hyde), `probes-v2/sources/hs-hyde.md:81-89`). LlamaIndex's `HyDEQueryTransform` is the one of the three that keeps them: with `include_original=True`, its default, it embeds the passage and the query's embedding strings ([base.py](https://raw.githubusercontent.com/run-llama/llama_index/main/llama-index-core/llama_index/core/indices/query/query_transform/base.py), `sources/li-query-transform.py:139-150`).
  - `MultiQueryRetriever` searches the query as given, first, then each version as a plain string. The three leaders with multi-query replace the whole query with the version; only the call's other arguments stay. So its retriever is a `Retriever<QueryType>`.
- `RetrieveOptions` does not change.

## Considered Options

- **A text for each node, by name, as Haystack.** It is the majority's address among the nine leaders (five of nine), and it lost. Four of the five write the tree in each request. Haystack builds a graph once and wires it by hand: its HyDE recipe connects the model's embedding to one named retriever. This package composes by wrappers built once (ADR 0008), and a wrapper cannot name the node below it. The node address needs a graph, which ADR 0008 rejected. The rule that decides is that of the leader whose composition ADR 0008 follows: LlamaIndex, by kind. If ADR 0008 is reopened, the named children of #5582 are the first step.
- **One string, as LangChain.** It lost: it is #5579 and #5580.
- **A rerank text beside the search text** (`{ text, rerankText }`, Meddit f386365). It lost: with a text for each kind of search, the information need is no search's text, so the reranker reads it. It fixes the reranker only.
- **An optional rerank text in the bundle**, as Weaviate's `rerank.query`. It lost for now: Weaviate defaults it to the search's query, and here the need is already apart from every search's text. No consumer asks for a third text.
- **A host's field in `RetrieveOptions`**, as Semantic Kernel's typed filter or Haystack's `retriever_kwargs`. It lost: a second text says what to look for, so a multi-query version must replace it with the query. Filtering is already `RetrieveOptions.filter` ([ADR 0009](./0009-a-filter-has-the-shape-of-haystacks-filters.md)).
- **A version that keeps the host's fields** (the first paper). It lost: the leaders replace the whole query, and Ezz ruled that the package is not shaped around one source's limits.
- **One embedding text, a string** (the first paper). It lost: no leader names it so; LlamaIndex's field is a list, and LlamaIndex and Haystack take the mean.
- **`embeddingStrs`**, the Python LlamaIndex's `embedding_strs` in camel case (paper v2). It lost to `customEmbeddings`, the name that LlamaIndex.TS gives the same field.
- **No plain string** (the first paper). It lost: LangChain, Haystack and Semantic Kernel take a string, and LlamaIndex takes either.
- **A conditional type that admits a string** (`Q | (QueryBundle extends Q ? string : never)`). It lost: `tsc` 5.9.3 cannot check the `in` annotation through it (TS2636).
- **A generic `HydeRetriever<Q>` over a `Retriever<Q>`** (the first build). It lost: HyDE builds a bundle from a string, and TypeScript cannot prove that a bundle is a `Q`. The build needed an overload of `bundleOf` with the return type `Exclude<Q, string>`, which `tsc` does not check, the same claim as an `as` assertion. Through it, a retriever of strings only compiled under HyDE and got a bundle. The sound form, a retriever of `Exclude<Q, string> | (string extends Q ? QueryBundle : never)`, does not compile in `tsc` 7.0.2: narrowing the query with `typeof` does not narrow `Q`, so neither branch of the bundle is a value of that type (TS2322, TS2698), and a plain retriever infers `Q = string`. A host gains nothing from it either, since only the embedding search reads the passage.
- **Two classes, one generic over the bundle of a host and one that takes a string.** It lost: it is sound, but it adds a second public class for one composite, which no leader has, for a host that fuses its source beside HyDE.
- **A fusion query type that intersects the query types of a tuple of children** (paper v2, `FusionRetriever<const R extends readonly Retriever<never>[]>`). It lost in the build: the fusion must call each child with the intersection, which needs an `as` assertion, and the base lint rule of `@zukhruf/eslint` refuses every assertion (`consistent-type-assertions`, `assertionStyle: 'never'`). `FusionRetriever<Q>` over `readonly Retriever<Q>[]` needs no assertion and gives the same type for one host child. Only two children with two other fields need the type argument.

## Consequences

- `retrieve('…')` keeps working wherever no host field is required. Only a call that gives other texts writes a bundle. The tests that passed a string still pass a string.
- Without `keywords`, a keyword child of a fusion reads the words of `query`, joined with AND (ADR 0004). A question so finds no passage that lacks one of its words. The leaders' keyword searches default to OR; that is a question for ADR 0004, and a later step of #5580 decides it.
- `MultiQueryRetriever` over a host child that needs its own field does not compile. Such a host derives its syntax from `query` in its adapter, as Semantic Kernel's Bing adapter, LangChain's `SelfQueryRetriever` and LlamaIndex's `AutoRetriever` do, or it is fused beside the multi-query search, not under it.
- An embedding retriever embeds several strings when `customEmbeddings` has several, and searches with their mean. When the model gives vectors of different dimensions for the texts of one query, the call fails with `DimensionMismatchError`, the first vector's dimensions as `expected` (ADR 0010): a broken model, not a caller bug, so the mean neither pads nor cuts.
- A `keywords` whose elements hold no word, such as `['  ']`, is a caller bug, the same state as an empty list: the keyword search throws a `RangeError` that names `keywords`, and does not give an empty list.
- One function of the package makes the bundle of a query, `bundleOf(query: QueryType): QueryBundle`. It is not generic: no composite builds a bundle of a host's query type.
- `HydeRetriever` over a host source that needs its own field does not compile. The host fuses the source beside HyDE.
- A bundle with one embedding slot cannot run two vector searches on two texts in one request, as Azure's list of vector queries does (`leaders-broad.md`, section 4). Two embedding searches with two texts are two children with two bundles, which needs the node address of #5582.
- #5582 (a result envelope, named children) changes what `retrieve` gives, not what it takes.
- #5583 (a rank or a score) changes `ScoredPassage`, not the query.
- #5584 (`Passage<M>`, `Filter<M>`) adds the metadata type as the second type parameter: `Retriever<Q, M>`, input first, output second, and `Postprocessor<M>`.

## Confirmation

The design comes from the leader tables. The paper and its evidence are in `~/.agent-backlog/handoff/zukhruf-retrieval-query-roles/`:

- `paper-v2.md`: six questions, each decided by a table of the nine leaders, with the line in each source (`probes-v2/sources/`, `sources/`).
- `leaders-broad.md`: the survey of 34 more packages (search engines, vector databases, RAG frameworks, rerank APIs) that confirmed it, with its sources in `sources-broad/`.
- `probes-v2/before-5579-rerank-text.out` and `probes-v2/before-5580-federation.out`: on the published 0.8.105, the reranker and MMR got `apixaban AND "renal insufficiency"[MeSH Terms]`, and the fusion gave every child the same string.
- `probes-v2/accept-5579-rerank-text.out` and `probes-v2/accept-5580-federation.out`: on a sketch of this API over the published leaves, the reranker got the question while the source got its own field, under HyDE too, and each child of a fusion read its own text. `probes-v2/tsc-accept-no-directive.out`, `tsc-accept.out` and `tsc-method-form.out`: the compile errors of a call without a host's field, of an empty list and of a `MultiQueryRetriever` over a host child, and that the method form of the port lets a host retriever pass as a plain one.

The tests of the change run through the public entry points. Each failed when its rule was broken in the source, and passed again when it was restored:

- `src/postprocessing-retriever.test.ts`, "a retriever that needs its own field gets the query bundle unchanged, while each postprocessor gets its query": fails when the postprocessors get the whole bundle as text, and when the retriever gets only `{ query }`.
- `src/hyde-retriever.test.ts`, "the passage reaches the embedding search only, as customEmbeddings": fails when the passage is the query (0.8.105), and when `keywords` is dropped.
- `src/hyde-retriever.test.ts`, "HyDE takes a retriever of any query bundle": a host source fused beside HyDE gets its field and no passage, and its `@ts-expect-error` lines, HyDE over a retriever of strings only and over the host source, are real errors, which the typecheck target proves. With the generic `HydeRetriever<Q>` and the overload of `bundleOf`, both are unused (TS2578).
- `src/multi-query-retriever.test.ts`, "a query bundle is searched as the caller gives it, first, and each version as a plain string": fails when a version keeps the fields of the bundle, when the bundle is searched as its `query` only, when it comes last, and when the prompt reads the whole bundle.
- `src/fusion-retriever.test.ts`, "each retriever gets the query bundle unchanged and reads its own text": a real `SqliteBM25Retriever` reads `keywords`, a real `SqliteEmbeddingRetriever` embeds `query` or `customEmbeddings`, and a host source gets its own field. It fails when the fusion gives each child only `{ query }`.
- The keyword retriever tests on SQLite, Postgres and SQL Server, "the words of keywords are quoted in place of the words of query": fail on SQLite and Postgres when `keywords` is ignored.
- The embedding retriever tests on SQLite, Postgres and SQL Server, "the texts of customEmbeddings are embedded in place of query, and two texts search with the mean of their vectors": fail on SQLite and Postgres when `customEmbeddings` is ignored, when `retrieve` or `retrieveMany` takes the first vector in place of the mean, and when `retrieveMany` groups the vectors by the index of the query.
- `src/fusion-retriever.test.ts`, "a fusion of plain retrievers takes a string as a query bundle with only query, and a fusion with a retriever that needs its own field takes neither, nor goes under MultiQueryRetriever": its `@ts-expect-error` lines are real errors, which the typecheck target proves. With the port as a method, three of them are unused (TS2578); with `keywords` as `readonly string[]`, the empty list compiles.
- The SQL Server tests skip on an engine that emulates amd64, as on this Mac (#5469), so their break-it check ran on SQLite and Postgres only. They run on CI.
